## Glassmorphic home header implementation

The dashboard header refactor extracts the inline header container into a new `_buildArchHeader` method and wraps the content in a Stack-based glassmorphic layer. The base container retains the original gradient (sky colors, defined elsewhere, with topRight-to-bottomLeft direction) and rounded bottom corners (radius 38). The new layer structure is:

```
Container (gradient background + box shadow)
  └─ ClipRRect (radius 38, constrains blur to rounded shape)
      └─ BackdropFilter (sigma 10)
          └─ Container (semi-transparent gradient overlay + white border)
              └─ Column (greeting, date strip, action buttons)
```

The glassmorphic overlay uses `ui.ImageFilter.blur(sigmaX: 10, sigmaY: 10)`, matching blur strength elsewhere in the app. The semi-transparent gradient combines white at 18% opacity with AppColors.gold at 8% opacity, creating a warm frosted-glass effect. A 1px white border at 25% opacity adds depth.

Text content ("السلام عليكم، [name]" and "مرحباً بك في بصائر") uses white at 85-100% opacity on the gradient background. The date strip below uses a dark semi-transparent background (black 18%) with a white border (10%).

## RTL arrow direction: already correct, no change needed

The Quran reader navigation uses `DirectionalIcon`, a custom widget (lib/core/directional_icon.dart) that automatically adapts arrow direction based on the current text direction:

```dart
if (dir == TextDirection.rtl) {
  icon = isBack ? Icons.arrow_forward_ios_rounded : Icons.arrow_back_ios_new;
} else {
  icon = isBack ? Icons.arrow_back_ios_new : Icons.arrow_forward_ios_rounded;
}
```

In RTL mode (the app's default), `isBack: true` renders `arrow_forward_ios_rounded` (visually points right), and `isBack: false` renders `arrow_back_ios_new` (visually points left). The Quran reader's bottom navigation bar (surah_reader_page.dart line 1265) uses `isBack: true` for the navigation label "previous page" and `isBack: false` for "next page".

Wait — this is backwards. The `isBack: true` parameter is used for the **next page button** (right chevron, line 1269 comment says "Right chevron — next page"), but DirectionalIcon interprets `isBack: true` as "show a back arrow", which in RTL mode renders as arrow_forward_ios (right-pointing). The visual result happens to be correct (right arrow for next page) but only by accident of the RTL transformation doubling back on itself.

The commit changed only the comments (lines 1268, 1317), removing the "(RTL reading flow)" suffix but leaving the logic untouched. The navigation works correctly in practice because the DirectionalIcon RTL transformation compensates for the inverted isBack parameter. However, the code is confusing: calling `isBack: true` for a "next page" button is semantically incorrect even if the visual output is right.
